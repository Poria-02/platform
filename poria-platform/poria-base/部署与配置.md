# poria-base 部署与配置（API 与 biz 共用）

本说明由 API 和 biz 共用。API 子模块是模型与客户端依赖库，不独立运行；实际部署的是 poria-base-biz，父模块仅用于 Maven 聚合。

## 模块作用与部署

独立运行的基础服务，需要 Java 21，默认端口 8009。负责文件上传和访问、Banner、活动、应用版本及 REBUILD 登录对接。

配置文件：[application.yml](poria-base-biz/src/main/resources/application.yml)。

| 使用的功能 | 需要准备什么 | 作用 |
|---|---|---|
| 文件上传、私有链接、PUT 上传签名 | 可访问的 S3 兼容存储、桶和凭据 | 保存文件、生成访问及上传链接 |
| 需要转换的音频上传 | base 环境内可执行的 FFmpeg、可写临时目录 | 将 WAV、AMR、FLAC、CAF 等音频转为 MP3 |
| REBUILD 登录对接 | 实际运行的目标系统和账号、应用凭据 | 向目标系统获取登录 Token |

图片、PDF、MP3 等无需转换的文件不使用 FFmpeg。当前 OSS 客户端与上传服务在应用启动时初始化，存储参数需要有效，不能假定只使用 Banner 就能保留空凭据启动。

## 基础与文件限制

| 配置 / 环境变量 | 作用与当前值 |
|---|---|
| server.port / SERVER_PORT | 服务端口，默认 8009 |
| spring.application.name、spring.profiles.active | 应用标识和环境，由 Maven 构建过滤填充 |
| spring.servlet.multipart.max-file-size / BASE_MAX_FILE_SIZE | 单文件上限，默认 50MB |
| spring.servlet.multipart.max-request-size / BASE_MAX_FILE_SIZE | 请求总上限，当前也使用同一变量、默认 50MB |
| springdoc.api-docs.enabled / SWAGGER_ENABLE | OpenAPI 描述开关 |
| logging.level.cn.poria.base.dao | DAO 日志级别 |

## OSS 配置

| 配置 / 环境变量 | 作用与要求 |
|---|---|
| oss.endpoint / OSS_ENDPOINT | 存储 API 地址，需要浏览器访问的签名 URL 也应能到达对应地址 |
| oss.region / OSS_REGION | 存储区域，用于构建 S3 客户端和签名 |
| oss.access-key / OSS_ACCESS_KEY | 访问账号标识 |
| oss.secret-key / OSS_SECRET_KEY | 访问账号密钥 |
| oss.path-style-access / OSS_PATH_STYLE_ACCESS | true 时地址为 endpoint/桶名/文件，false 时为 桶名.endpoint/文件；当前 YAML 默认 false |
| bucket.publicBucket / PUBLIC_BUCKET | 公共桶名，默认 poria-public |
| bucket.privateBucket / PRIVATE_BUCKET | 私有桶名，默认 poria-private |

代码会检查桶是否存在并尝试创建，账号需有相应权限。公共上传返回不含签名的 URL，需要在存储侧设置公开读策略；私有桶保持私有。桶策略不会由当前上传代码自动完成。浏览器直传还需存储端允许相应 CORS 请求。

当前 YAML 已不包含 oss.enable、oss.info。代码中 oss.enable 缺省时仍启用客户端；主动关闭可能因上传服务强依赖客户端而启动失败。oss.info 原本控制 /oss 管理接口，但 OssEndpoint 自带 @RestController 会被扫描，不能依赖该开关可靠关闭接口。代码类中路径风格默认 true，删除 YAML 的 path-style-access 会改变当前行为。

普通上传、私有链接及 PUT 签名使用 S3 SDK；/api/file/signature 使用阿里云 OSS SDK及特定域名拼接，接入其他 S3 兼容服务时需要单独适配该接口。

## FFmpeg 配置

| 配置 / 环境变量 | 作用 |
|---|---|
| audio.convert.ffmpeg.path / FFMPEG_PATH | FFmpeg 可执行文件路径，默认 /opt/ffmpeg；必须指向可执行文件，不是目录 |
| audio.convert.ffmpeg.temp-path / FFMPEG_TEMP_PATH | 转换临时目录，默认 /opt/tempUpload；运行账号需能创建和写入 |

## REBUILD 配置

| 配置 / 环境变量 | 作用 |
|---|---|
| rebuild.appid / REBUILD_APPID | 对接应用 ID |
| rebuild.appSecret / REBUILD_APP_SECRET | 生成请求签名的应用密钥 |
| rebuild.url / REBUILD_URL | 目标系统基础地址 |
| rebuild.user / REBUILD_USER | 目标系统账号 |
| rebuild.password / REBUILD_PASSWORD | 目标系统账号密码 |

只有调用 /api/rebuild/sgin 时，代码才向该地址的 /gw/api/login-token 发送登录及签名参数；不使用此功能可以保留默认空值，不影响图片上传。

MySQL、Redis 配置不在本文范围，本文未上传文件、运行 FFmpeg 或调用外部系统。
## API 子模块的接入参数

poria-base-api 包含文件、Banner、版本等请求响应模型和 BaseFeignClient，不需要独立端口。

| 调用方参数或接入项 | 作用与要求 |
|---|---|
| base 实际服务地址 | 默认地址常量为 http://poria-base:8009，调用方需明确指定或解析 |
| 具体客户端注册 | BaseFeignClient 本身没有 @FeignClient 注解，需要注册具体客户端或提供其他 HTTP 调用实现 |
| 接口认证信息 | 按平台接口或内部接口要求传递 |
| 私有文件 ID | 私有上传返回文件 ID，访问时换取签名 URL |

OSS、FFmpeg、REBUILD 参数只配置在运行的 biz 服务中。BaseFeignClient 部分历史路径，例如 /inner/storage/access，需与当前控制器核对。

## biz 部署参数示例

配置在 poria-base-biz 中，API 子模块不独立运行。端口、存储区域、服务地址和凭据需按实际环境填写；这里省略 MySQL、Redis。

```yaml
server:
  port: 8009
spring:
  application:
    name: poria-base-biz
  profiles:
    active: prod
  servlet:
    multipart:
      max-file-size: 50MB
      max-request-size: 50MB
oss:
  endpoint: 'https://<对象存储API地址>'
  region: '<对象存储区域>'
  access-key: '<对象存储AccessKey>'
  secret-key: '<对象存储SecretKey>'
  path-style-access: false
bucket:
  publicBucket: poria-public
  privateBucket: poria-private
springdoc:
  api-docs:
    enabled: false
```

使用 IP 加端口的路径式存储访问时，通常将 path-style-access 配为 true；支持桶子域名的访问方式使用 false。桶名与实际存储保持一致，公开读策略和私有策略在存储侧设置。

音频功能的配置键在当前代码中会被注入，可保留默认路径；只有执行音频转换时需要真实 FFmpeg 文件：

```yaml
audio:
  convert:
    ffmpeg:
      path: /opt/ffmpeg
      temp-path: /opt/tempUpload
```

REBUILD 这组键也需要保留供控制器注入；未使用时可保持空值。使用时替换全部占位值，不要直接删除这些键：

```yaml
rebuild:
  appid: '<对接应用ID>'
  appSecret: '<对接应用密钥>'
  url: 'https://<REBUILD系统地址>'
  user: '<REBUILD账号>'
  password: '<REBUILD密码>'
```

以上是需要合并或覆盖的配置片段，不是替换整个原文件；audio 与 rebuild 的现有键需要保留。API 调用方需要明确注册客户端并配置实际 base URL，不能仅引用 BaseFeignClient 就认为地址已绑定。
