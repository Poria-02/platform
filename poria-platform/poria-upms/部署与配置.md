# poria-upms 部署与配置（API 与 biz 共用）

本说明由 API 和 biz 共用。API 子模块是模型与客户端依赖库，不独立运行；实际部署的是 poria-upms-biz，父模块仅用于 Maven 聚合。

## 模块作用与部署

独立运行的管理业务服务，需要 Java 21，默认端口 4000。提供用户、角色、菜单、部门、字典、标签、参数、动态路由、令牌管理及日志查询等接口。访问接口需要平台认证及对应权限。

账号密码管理不需要 OSS 或 FFmpeg。使用短信发送功能时需要另行准备消息服务；令牌管理的部分调用需要能访问 auth。

配置文件：[application.yml](poria-upms-biz/src/main/resources/application.yml)。

## 公共参数备注字段

公共参数页面的备注使用 `remarks` 字段，支持新增、修改和编辑回显，最多 500 个字符；提交空字符串可以清空已有备注。

启用此版本前，在 UPMS 实际使用的数据库中执行 [公共参数备注增量 SQL](../sql/poria_upms_public_param_remarks.sql)，补充 `sys_public_param.remarks` 列。脚本支持重复执行，已存在该列时跳过。先执行 SQL，再由部署人员重新构建并启动 UPMS 服务，避免新代码查询尚未添加的列。

## 需要配置什么

| 配置 / 环境变量 | 作用与要求 |
|---|---|
| server.port | HTTP 端口，当前 4000 |
| spring.application.name | 应用标识，当前 poria-upms-biz |
| spring.profiles.active | 当前 YAML 固定为 dev，生产运行时应覆盖为实际环境 |
| auth.encodeKey / ENCODE_KEY | 用户新增、改密等字段的 AES 解密密钥；与 auth 和前端配置一致，前端当前要求 16 字节 |
| auth.enable / ENCRYPT_ENABLE | 认证配置类中定义的加密开关；当前部分用户写入逻辑直接解密，不要假定设为 false 会关闭所有 AES 解密 |
| write.mobiles / LOGIN_MOBILES | 逗号分隔的手机号列表；名单中的手机号跳过短信发送流程中的一处 IP 限流检查，不是整个平台的登录白名单 |
| spring.servlet.multipart.max-file-size | 单文件上限，当前 20MB |
| spring.servlet.multipart.max-request-size | 单次请求文件总上限，当前 100MB |
| springdoc.api-docs.enabled / SWAGGER_ENABLE | OpenAPI 描述开关 |
| logging.level.cn.poria.upms.mapper | Mapper 日志级别，当前 debug |
| PORIA_auth | 部分令牌管理调用的认证服务地址，默认 http://poria-auth:3000；源码变量使用这个大小写 |

## 短信功能的实际依赖

当前 sendSmsCode 直接调用 http://poria-message:8007/inner/sms/send。仓库没有该服务，也没有在此调用处读取可配置的消息 URL。启用短信时必须提供相应服务和可解析主机名，或先修改该调用；仅设置 PORIA_MESSAGE 不会自动覆盖这段固定 URL。

前端的 OAuth 客户端配置应与这里维护的客户端信息一致。公共 Kafka 日志、监控等按功能选择，不是每项基础管理功能都必须启用。

MySQL、Redis 配置不在本文范围，本文未发送短信或验证业务接口。
## API 子模块的接入参数

poria-upms-api 包含用户、角色、部门、菜单等模型和 Feign 客户端，不需要新增服务端口。

| 调用方参数或接入项 | 作用与要求 |
|---|---|
| PORIA_UPMS | 指向本模块 biz 服务，当前默认 http://poria-upms:4000 |
| PORIA_auth | RemoteTokenService 指向认证服务，当前默认 http://poria-auth:3000，注意变量大小写 |
| Feign 客户端注册 | 引用 API 依赖后由调用方注册需要的客户端 |
| 用户令牌或内部调用认证 | 按目标接口要求提供，不会因引用 API 自动获得权限 |
| 请求超时、业务返回检查 | 由调用方配置，详见 [Feign 公共模块](../poria-common/poria-common-feign/部署与配置.md) |

## biz 部署参数示例

配置位置为 poria-upms-biz 的 application.yml 或其外部覆盖配置，API 子模块不重复配置这些参数。

```yaml
server:
  port: 4000
spring:
  application:
    name: poria-upms-biz
  profiles:
    active: prod
  servlet:
    multipart:
      max-file-size: 20MB
      max-request-size: 100MB
auth:
  enable: true
  encodeKey: '<与auth和前端一致的16字节密钥>'
write:
  mobiles: ''
PORIA_auth: 'http://<认证服务地址>:3000'
springdoc:
  api-docs:
    enabled: false
logging:
  level:
    cn.poria.upms.mapper: info
```

write.mobiles 可为空；需要该短信限流例外名单时再填逗号分隔的手机号。需要短信时另准备代码写死的 poria-message:8007 服务地址，当前没有可直接覆盖该调用的 YAML 参数。

API 调用方的地址参数示例（作为进程环境变量提供，不会自动读取任意 .env 文件）：

```dotenv
PORIA_UPMS=http://<UPMS服务地址>:4000
PORIA_auth=http://<认证服务地址>:3000
```
