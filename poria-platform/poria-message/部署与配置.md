# poria-message 部署与配置

从 `unhm-support/unhm-message` 复制并适配 Poria。父模块用于 Maven 聚合，API 子模块提供 `MessageApi` 和请求响应模型，实际运行的是 `poria-message-biz`，要求 Java 21，默认端口 8007。

保留短信、钉钉、微信及小程序消息、待办和任务日志、腾讯 IM/TRTC/VOD、问卷转发、云信小号、外呼、内容审核及语音识别接口。HTTP 路径仍使用 `/app/**`、`/inner/**`、`/api/**`。音频审核沿用原项目的未实现状态。

## 编译和部署

在 `poria-platform` 目录执行：

```powershell
mvn -pl poria-message/poria-message-biz -am -DskipTests package
```

产物为 `poria-message/poria-message-biz/target/poria-message-biz.jar`。配置环境变量后，由部署人员启动：

```powershell
java -jar poria-message/poria-message-biz/target/poria-message-biz.jar
```

网关采用已有的动态路由机制，需要在路由管理中配置 `/message/**` 指向消息服务的 8007 端口，并移除一层 `/message` 前缀（`StripPrefix=1`）。其他模块的 Feign 客户端可继承 `cn.poria.message.api.MessageApi`，使用 `ServiceNameConstants.MESSAGE_SERVICE` 作为 URL；环境变量 `PORIA_MESSAGE` 可覆盖地址。

新库建表脚本为 `../sql/poria_message.sql`，包含 12 张表，不包含业务数据。脚本仅创建缺失表，不会升级已有表，也不会导入原项目模板或日志。已有数据库请先比对结构；模板 `create_by` 已改为字符串，以匹配 Poria 的账号字段和自动填充逻辑。本次迁移没有执行 SQL。

## 基础配置

配置文件位于 `poria-message-biz/src/main/resources/application.yml` 和 `application-kafka.yml`。原项目的账号密钥不随模块复制。

| 环境变量 | 用途与默认值 |
|---|---|
| `SERVER_PORT` | 服务端口，8007 |
| `MYSQL_HOST`、`MYSQL_PORT`、`MYSQL_USERNAME`、`MYSQL_PASSWORD` | MySQL 连接；默认 localhost、3306、root、空密码 |
| `MESSAGE_DATABASE` | 数据库名称，poria_message |
| `REDIS_HOST`、`REDIS_PORT`、`REDIS_PASSWORD` | Redis 连接；默认 localhost、6379、空密码 |
| `SWAGGER_ENABLE` | OpenAPI 描述开关，true |
| `MESSAGE_SQL_LOG_LEVEL` | DAO 日志级别，info |
| `KAFKA_BOOTSTRAP_SERVERS` | Kafka 地址，localhost:9092 |
| `MESSAGE_KAFKA_ENABLED` | 健康宣教阅读状态的 Kafka 消费监听开关，false |
| `KAFKA_SECURITY_PROTOCOL` | Kafka 连接协议，PLAINTEXT |
| `KAFKA_SASL_MECHANISM`、`KAFKA_SASL_JAAS_CONFIG` | 需要 SASL 时配置机制和完整 JAAS 字符串 |

`kafka` profile 默认包含，以提供公共模块要求的 `poriaKafkaTemplate`。消费开关不控制发送；腾讯 IM 和视频回调仍会向原有主题发送消息，使用回调功能时需要配置可用的 Kafka。

## 远程业务服务

Poria 当前没有 customer、staff、visual、tduck 业务模块。消息服务将实际使用的接口和模型保存在自己的 `integration` 包中，不依赖这些旧项目的 Maven 包；仍须对接提供对应 HTTP 接口的服务。

| 环境变量 | 默认地址 | 使用场景 |
|---|---|---|
| `PORIA_BASE` | http://poria-base:8009 | 文件服务 |
| `PORIA_UPMS` | http://poria-upms:4000 | 公共参数和权限相关接口 |
| `PORIA_CUSTOMER` | http://poria-customer:8004 | 用户绑定、企业公众号信息 |
| `PORIA_STAFF` | http://poria-staff:8005 | 云信实名认证结果回写 |
| `PORIA_WXMP` | http://poria-wxmp:9994 | 公众号模板消息 |
| `PORIA_WXMA` | http://poria-wxma:8023 | 小程序订阅消息 |
| `PORIA_ALIMA` | http://poria-alima:8034 | 支付宝模板消息 |
| `PORIA_TDUCK` | http://poria-tduck:8998 | 问卷列表、流水号和回填信息 |

默认主机名仅是部署约定，不表示仓库已包含或部署相应服务。可将这些变量设置为现有兼容服务地址。

## 消息渠道

按使用的渠道配置，变量和配置键的对应关系见 YAML：

| 功能 | 环境变量 |
|---|---|
| 阿里短信 | `SMS_ALI_ACCESS_KEY_ID`、`SMS_ALI_ACCESS_KEY_SECRET`、`SMS_ALI_SIGN` |
| 移动 MAS | `SMS_MAS_EC_NAME`、`SMS_MAS_AP_ID`、`SMS_MAS_SIGN`、`SMS_MAS_SECRET_KEY`、`SMS_MAS_URL` |
| 联通短信 | `SMS_LT_LOGIN_NAME`、`SMS_LT_PASSWORD`、`SMS_LT_URL` |
| 电信短信 | `SMS_ESURFING_URL`、`SMS_ESURFING_APP_KEY`、`SMS_ESURFING_APP_SECRET`、`SMS_ESURFING_REPORT_URL`、`SMS_ESURFING_MO_URL` |
| 网易短信 | `SMS_NTES_URL`、`SMS_NTES_APP_KEY`、`SMS_NTES_APP_SECRET`、`SMS_NTES_NONCE`、`SMS_NTES_BUSINESS_ID` |
| 网易消息配置 | `NETEASE_APP_KEY`、`NETEASE_APP_SECRET` |
| 腾讯 IM | `TX_IM_SDK_APP_ID`、`TX_IM_SECRET_KEY`、`TX_IM_ADMIN_ACCOUNT`、`TX_IM_SIGN_EXPIRE_TIME` |
| 腾讯 TRTC | `TX_TRTC_SDK_APP_ID`、`TX_TRTC_SECRET_ID`、`TX_TRTC_SECRET_KEY`、`TX_TRTC_ADMIN_ACCOUNT`、`TX_TRTC_SIGN_EXPIRE_TIME`、`TX_TRTC_CALLBACK_URL` |
| 腾讯 VOD | `TX_VOD_SDK_APP_ID`、`TX_VOD_SIGN_EXPIRE_TIME`；SDK 客户端沿用 TRTC 的 SecretId 和 SecretKey |
| 外呼 | `MESSAGE_CALL_URL`、`MESSAGE_CALL_APP_ID`、`MESSAGE_CALL_SECRET_KEY` |
| 云信小号 | `YXXH_BASE_URL`、`YXXH_APP_ID`、`YXXH_TOKEN` |
| 阿里内容审核 | `ALI_CONTENT_ACCESS_KEY_ID`、`ALI_CONTENT_ACCESS_KEY_SECRET` |
| 阿里语音识别 | `ALI_ASR_API_KEY` |
| 消息链接转换、随访对接 | `MESSAGE_CONVERT_URL`、`MESSAGE_FOLLOW_URL` |

云信小号地址为服务根地址，不带 `/voice/1.0.0` 路径。外呼地址沿用原接口拼接规则，需要以 `/` 结尾。钉钉机器人地址、签名及各渠道消息模板仍在数据库模板中维护；相关 UPMS 参数包括 `PLAT_DEFAULT_ORG_ID` 和 `API_DOMAIN`。

阿里内容审核客户端改为按需初始化。TRTC 回调地址默认为空；配置非空 `TX_TRTC_CALLBACK_URL` 时，原有初始化逻辑会在启动阶段向腾讯注册回调。实际消息发送、回调和第三方接口联调需要部署人员另行执行。

本次验证使用本地 Maven 缓存执行离线编译；未启动应用、连接数据库或调用第三方服务。
