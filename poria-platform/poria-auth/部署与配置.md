# poria-auth 部署与配置

## 模块作用与部署

独立运行的认证服务，默认 HTTP 端口 3000。负责平台登录、验证码校验、令牌签发、刷新和退出。需要 Java 21，并能访问 UPMS 服务；普通账号密码登录无需另行部署 REBUILD、FFmpeg 或 XXL-Job。

配置文件：[application.yml](src/main/resources/application.yml)。

## 需要配置什么

| 配置 / 环境变量 | 作用与要求 |
|---|---|
| server.port | 认证服务端口，默认 3000 |
| spring.application.name、spring.profiles.active | 应用名和运行环境；当前由 Maven 过滤填充 |
| auth.enable / ENCRYPT_ENABLE | 登录字段 AES 解密开关，当前默认 true，不是整个认证服务的开关 |
| auth.encodeKey / ENCODE_KEY | 登录字段解密密钥；与前端 VITE_AUTH_ENCODE_KEY、UPMS 使用的密钥保持一致。当前前端要求 UTF-8 编码后 16 字节 |
| PORIA_UPMS | UPMS 调用地址，默认 http://poria-upms:4000；用于读取用户、角色、OAuth 客户端等信息 |
| OAuth 客户端信息 | 在 UPMS 中维护；前端客户端 ID、Secret、授权类型和 scope 需与其一致 |
| springdoc.api-docs.enabled / SWAGGER_ENABLE | 控制 OpenAPI 接口描述是否启用 |
| ky.host / KY_HOST | YAML 中存在的预留服务地址；当前未发现 Java 代码读取，不作为普通登录必需组件 |

## 配置与代码的实际关系

前端当前会加密用户名、密码后调用 /auth/plat/login。仅关闭后端 auth.enable 而保持前端加密，会导致双方协议不一致。auth 配置类中的 HIS Token 地址也是预留字段，当前未见使用入口。

Kafka、日志投递和追踪属于公共组件的可选能力，参见 [日志模块](../poria-common/poria-common-log/部署与配置.md) 和 [Kafka 模块](../poria-common/poria-common-kafka/部署与配置.md)。不要将注释中的历史业务模块当作必须部署的服务。

MySQL、Redis 配置不在本文范围。本文仅核对源码，未验证实际登录。

## 部署参数示例

以下为运行时需要明确填写的配置；替换占位值后合并到认证服务配置。MySQL、Redis 参数省略。

```yaml
server:
  port: 3000
spring:
  application:
    name: poria-auth
  profiles:
    active: prod
auth:
  enable: true
  encodeKey: '<与前端和UPMS一致的16字节密钥>'
PORIA_UPMS: 'http://<UPMS服务地址>:4000'
springdoc:
  api-docs:
    enabled: false
```

密钥为必填替换项；端口、服务地址和环境按实际部署填写。ky.host 当前未见有效读取，不列为需要部署的参数。
