# poria-common-security 部署与配置

## 模块作用与部署

认证授权公共库，不独立部署。宿主业务服务使用 EnablePlatResourceServer 等配置开启接口认证，结合用户权限、内部接口检查及 XSS 字符串处理。平台认证由 poria-auth 服务承担。

## 配置什么及作用

| 配置或接入项 | 作用 |
|---|---|
| security.oauth2.ignore.urls | 额外允许匿名访问的路径列表，应只填写实际需要的接口 |
| @EnablePlatResourceServer | 引入资源服务器安全配置，不是另一个运行进程 |
| @PreAuthorize 与 @pms.hasPermission | 控制具体业务权限 |
| @Inner | 内部接口标记，同时通过 @Hidden 隐藏 Swagger / OpenAPI 文档；包含 @Inner(false)，适用于类和方法。当前鉴权实现主要检查固定 from 请求头，不等于可验证的服务身份 |
| mica.xss.enabled | 字符串清理功能开关，缺省启用 |
| mica.xss.mode | clear、escape、validate 等处理模式，当前缺省 clear |
| mica.xss.form.*、mica.xss.jackson.* | 表单与 JSON 字符串的 trim、字符处理等选项 |
| mica.xss.path-patterns、path-exclude-patterns | 路径相关配置，实际范围需核对当前拦截器实现，不能只凭名称认定排除已经生效 |

配置参考 [PermitAllUrlProperties](src/main/java/cn/poria/common/security/component/PermitAllUrlProperties.java) 和 [MicaXssProperties](src/main/java/cn/poria/common/security/xss/config/MicaXssProperties.java)。

## 运行关系

当前匿名默认列表包括 /actuator/**、文档相关路径等，并会把 @Inner 标记的路径加入放行列表；内部接口依赖额外检查。网关会清洗外部 from 头，但直接访问业务端口时不能依靠网关，部署网络和接口权限需要相匹配。

Feign 的认证透传仅在相应用户请求上下文存在时可用，定时任务没有浏览器用户令牌可自动透传。无需部署独立 XSS 服务。

MySQL、Redis 的部署与连接配置按要求不展开。本文未验证实际权限。

## 宿主服务参数示例

本模块没有独立监听参数。下面显式保留认证和 XSS 处理；ignore.urls 仅表示额外匿名路径，不会移除代码内置的放行列表。

```yaml
security:
  oauth2:
    ignore:
      urls: []
mica:
  xss:
    enabled: true
    mode: clear
    form:
      trim-text: true
      empty-as-null: false
    jackson:
      trim-text: true
      empty-as-null: false
```

有明确匿名接口时再向 urls 添加路径。权限、内部接口和资源服务器 Bean 仍需代码正确接入，不能只填这一段就获得完整认证。
