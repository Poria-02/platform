# poria-common-kafka 部署与配置

## 模块作用与部署

Kafka 客户端依赖库，不独立运行。提供 poriaKafkaTemplate 和 KafkaUtil 发送方法。实际使用需要准备 Kafka Broker、主题以及匹配的连接和认证策略。

## 配置什么及作用

来源：[application-kafka.yml](src/main/resources/application-kafka.yml)、[KafkaAutoConfiguration](src/main/java/cn/poria/commom/kafka/KafkaAutoConfiguration.java)。

| 配置 / 环境变量 | 作用与要求 |
|---|---|
| spring.profiles.include=kafka | 激活 kafka profile；配置类带 @Profile，未激活不会创建自定义生产者 |
| spring.kafka.bootstrap-servers / KAFKA_BOOTSTRAP_SERVERS | Broker 地址，当前默认 poria-kafka:9096，不代表实际 Broker 已部署在该端口 |
| spring.kafka.poria-producer.key-serializer、value-serializer | 自定义生产者的 key/value 编码方式，当前 StringSerializer |
| spring.kafka.poria-producer.properties.security.protocol | 自定义生产者的连接协议，当前 SASL_PLAINTEXT |
| spring.kafka.poria-producer.properties.sasl.mechanism | 认证机制，当前 SCRAM-SHA-512 |
| spring.kafka.poria-producer.properties.sasl.jaas.config | Broker 账号认证配置，需按实际环境提供，不复制现有凭据 |
| spring.kafka.consumer.* | 消费端反序列化、连接认证等配置；实际消费者仍需注册 |
| 实际业务主题和消费组 | 调用方或消费者定义，不会由工具类自动补齐业务消费链路 |

SASL_PLAINTEXT 提供认证但不加密传输；使用其他协议时按部署的 Broker 设置相应客户端参数。

## 现有实现的边界

仓库未见 @KafkaListener 消费者，KafkaUtil 是发送封装。普通 send 未检查异步发送结果，可靠业务消息仍需失败处理、重试和消费去重。

“延时发送”只向 PORIA_DELAY_QUEUE 附加 delaySeconds、targetTopic 消息头，未见延时转发消费者，不能直接当作完整延时队列。

YAML 的 poria-producer.properties.max.request.size 等扩展项没有全部写入当前自定义 ProducerFactory 参数，不能保证仅修改 YAML 就全部生效。日志 appender 使用另一套 KAFKA_HOST 和参数，详见 [日志模块](../poria-common-log/部署与配置.md)。

MySQL、Redis 不在本文范围，本文未连接 Broker 或发送消息。

## 宿主服务部署参数示例

替换 Broker 地址和 SCRAM 账号密码，协议需与 Broker 一致。profile 和其他已有 spring 配置应合并，不要重复定义顶层 spring。

```yaml
spring:
  profiles:
    include: kafka
  kafka:
    bootstrap-servers: '<Broker地址>:<Broker端口>'
    poria-producer:
      key-serializer: org.apache.kafka.common.serialization.StringSerializer
      value-serializer: org.apache.kafka.common.serialization.StringSerializer
      properties:
        security:
          protocol: SASL_PLAINTEXT
        sasl:
          mechanism: SCRAM-SHA-512
          jaas:
            config: 'org.apache.kafka.common.security.scram.ScramLoginModule required username="<Kafka账号>" password="<Kafka密码>";'
```

这是当前自定义生产者读取的参数形状，未包含代码没有转交的扩展项。需要消费时再增加相应 consumer 配置和实际消费者代码；不能只部署 Broker 期待业务消息被自动处理。
