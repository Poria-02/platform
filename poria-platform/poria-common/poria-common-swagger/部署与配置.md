# poria-common-swagger 部署与配置

## 模块作用与部署

接口文档辅助库，不独立运行，不需要另部署 Swagger 服务。API 描述和页面由引入 springdoc 的宿主服务提供。

## 配置什么及作用

| 配置 | 作用与当前接入情况 |
|---|---|
| springdoc.api-docs.enabled | 实际 OpenAPI 描述的开关，在各业务服务 YAML 中配置 |
| springdoc.swagger-ui.enabled | 引入 UI 支持的应用可用此项控制文档界面 |
| springdoc.api-docs.path | API 描述的访问路径 |
| swagger.enabled | 本模块历史辅助配置的开关，当前默认 true，不能当作所有 springdoc 接口的统一关闭开关 |
| swagger.title、gateway、tokenUrl、scope、services | 预留的文档标题、服务及授权展示信息；当前 OpenAPI Bean 生成代码已注释，不能承诺填写后全部生效 |
| swagger.basePackage、basePath、excludePath、ignoreProviders | 配置类保留的扫描及过滤字段，当前未见完整生效逻辑 |

来源：[SwaggerProperties](src/main/java/cn/poria/common/swagger/support/SwaggerProperties.java)、[SwaggerAutoConfiguration](src/main/java/cn/poria/common/swagger/config/SwaggerAutoConfiguration.java)。

平台公共 @Inner 注解已包含 @Hidden：标记 @Inner 或 @Inner(false) 的方法均不展示在文档中，标记整个类则隐藏该类的接口。隐藏依据是注解，而不是 URL 中是否含 inner；未标记的业务接口不受该规则影响。此设置只控制文档展示，不改变接口调用和认证逻辑。

运行文档功能仍需明确宿主应用引入的 springdoc 依赖与实际文档路径；不是仅有这份配置类就具备完整文档界面。MySQL、Redis 无需在本文配置，本文未访问运行中的文档接口。

## 宿主服务参数示例

生产环境不展示接口文档时，可明确配置：

```yaml
springdoc:
  api-docs:
    enabled: false
  swagger-ui:
    enabled: false
swagger:
  enabled: false
```

需要文档时改为 true，并确认宿主应用确实引入相应 API/UI 依赖。后一个 swagger 开关只对应历史辅助类，不能替代前两个实际 springdoc 开关。
