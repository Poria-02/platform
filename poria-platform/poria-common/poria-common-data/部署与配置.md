# poria-common-data 部署与配置

## 模块作用与部署

数据访问依赖库，不独立运行。提供 MyBatis-Plus 配置、分页、创建修改字段填充、字段加密处理、字典标签转换和数据权限。MySQL、Redis 的部署和连接配置按要求省略。

## 配置什么及作用

参考 [application.yml](src/main/resources/application.yml)，实际运行时确保宿主服务加载所需配置。

| 配置或代码设置 | 作用 |
|---|---|
| mybatis-plus.mapper-locations | Mapper XML 位置，当前 classpath:/mapper/*Mapper.xml |
| mybatis-plus.type-handlers-package | 自定义字段处理器包 |
| mybatis-plus.global-config.db-config.id-type | 主键生成策略，当前配置 auto，实体字段注解也会影响实际策略 |
| insert-strategy、update-strategy | 控制哪些字段参与新增或修改，当前 not_empty |
| configuration.jdbc-type-for-null | 空值使用的 JDBC 类型设置 |
| configuration.call-setters-on-nulls | 查询字段为空时是否仍调用 setter |
| PaginationInnerInterceptor | 代码中的分页组件，当前最大分页量 1000 |
| DataScope 参数、数据范围字段 | 配合范围查询计算用户、部门权限，不是自动的全表租户隔离 |

## 需要哪些业务服务

默认数据范围实现使用 UPMS 的角色和部门客户端，需要实际部署 UPMS、提供可达的 PORIA_UPMS 地址，并正确传递对应认证信息。RestDataScopeRoleProvider 是可替换实现，其 upmsUrl 由创建它的调用方提供，不是本模块已经定义的 YAML 开关。

当前部分转换切面直接拼接 ServiceNameConstants.UPMS_SERVICE 作为 RestTemplate URL，部署前需确认占位符已解析，不能仅凭环境变量存在就保证这些转换调用正确。

当前 MybatisPlusConfiguration 注册数据范围与分页拦截器，未注册统一租户拦截器。实体字段存在 tenantId 不代表已经提供多租户隔离；缺少 DataScope 的查询也不会自动获得相同范围限制。

配置中的 work-id、datacenter-id 属于现有属性，但代码另有 IdentifierGenerator Bean，实际 ID 行为以实体和生成器为准。本文未执行数据查询。

## 宿主服务参数示例

这是 ORM 行为配置，不是另一个服务的部署配置；只列代码中实际使用的主要设置，连接参数省略。

```yaml
mybatis-plus:
  mapper-locations: classpath:/mapper/*Mapper.xml
  type-handlers-package: cn.poria.common.data.handler
  global-config:
    banner: false
    db-config:
      id-type: auto
      insert-strategy: not_empty
      update-strategy: not_empty
  configuration:
    jdbc-type-for-null: 'null'
    call-setters-on-nulls: true
```

需要默认数据范围远程调用时，另在宿主环境填写 PORIA_UPMS=http://<UPMS服务地址>:4000，并提供目标接口要求的认证。
