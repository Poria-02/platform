# poria-common-log 部署与配置

## 模块作用与部署

宿主服务的日志依赖库，不是独立 poria-log 服务。提供控制台日志、TraceId、操作日志切面及可选 Kafka 日志投递。

| 使用方式 | 需要准备什么 |
|---|---|
| 控制台日志 | 不需要额外日志服务器 |
| 启用 log profile 发送日志 | Kafka Broker 和 poria-log 主题；如需存储和查询，还要实际提供消费与存储端 |
| 完整 SkyWalking 追踪 | Agent、OAP 和所需查看界面；本仓库没有提供它们的部署实现 |

## 配置什么及作用

来源：[application-log.yml](src/main/resources/application-log.yml)、[logback-spring.xml](src/main/resources/logback-spring.xml)。

| 配置 / 变量 | 作用与要求 |
|---|---|
| spring.profiles.include=log | 加载日志 profile 配置，并将根日志交给 Kafka appender |
| KAFKA_HOST | Broker 地址；Logback 直接读取此变量，YAML 中另有 127.0.0.1:9092 缺省值，不能假定该缺省会自动填入 Logback |
| HOSTNAME、CONTEXT_NAME | 日志来源及生产者标识，按宿主环境实际提供 |
| LOGGING_PATH | 日志初始化器使用的路径，未提供时回退 logs；需配置类生效且目录可写 |
| ACTUATOR_ENDPOINTS | 需要暴露的管理端点列表，当前缺省为空；仅暴露实际需要的端点 |
| management.server.port | 此 profile 当前设置 7888，同机多个应用启用时需分别配置避免冲突 |
| sw.enabled / SW_ENABLED | 自定义 TraceIdFilter 的选择开关；false 条件下使用自定义 TraceId，不会因设为 true 就自动加载 Agent |
| SkyWalking Agent 的服务名和 OAP 地址 | 由实际 Java Agent 部署配置提供，本库未指定完整采集端地址 |

## 现有实现的边界

logback 中的 kafka-doris 是 appender 名称与历史用途注释，不代表仓库已经包含 Doris 或日志消费链路。实际 Logback 生产者使用 acks=0，不能把它当作必达审计日志。

SysLogAspect 当前构造操作日志但未实际发布或持久化，相关 Kafka 发送被注释；仅部署 Kafka 不会自动补齐审计落库。错误及登录日志也有注释掉的发送逻辑。

MySQL、Redis 配置不在本文范围，本文未发送日志或部署追踪组件。

## 按需启用的部署参数

需要 Kafka 日志投递时，宿主服务增加 log profile，以下片段应与现有 spring 配置合并：

```yaml
spring:
  profiles:
    include: log
management:
  server:
    port: 7888
  endpoints:
    web:
      exposure:
        include: health,info
sw:
  enabled: false
```

运行宿主进程时提供环境变量：

```dotenv
KAFKA_HOST=<Broker地址>:<Broker端口>
HOSTNAME=<当前节点标识>
CONTEXT_NAME=<当前应用标识>
LOGGING_PATH=<运行账号可写的日志目录>
```

同机多个服务启用此配置时，7888 必须分别调整。Kafka 日志 topic 当前为 poria-log。不需要 Kafka 日志时不启用 log profile，管理端点仍可在应用配置中单独指定。

完整 SkyWalking 需要真实 Agent 和 OAP 部署配置，sw.enabled=true 不是部署参数的替代品。
