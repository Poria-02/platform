# poria-common-gateway 部署与配置

## 模块作用与部署

响应式网关的动态路由库，不独立运行。由 poria-gateway 引入，监听端口由网关应用决定。当前依靠共享路由存储与刷新通知同步网关缓存，相关存储连接配置不在本文范围。

## 配置什么及作用

| 项目 | 作用 |
|---|---|
| @EnablePlatDynamicRoute | 网关应用引入动态路由组件 |
| 路由 URI | 实际目标服务地址，从网关所在环境可达 |
| Path 谓词及路径前缀 | 决定请求匹配哪条路由 |
| filters | 配置路径转换、限流等路由过滤行为 |
| 路由刷新 | 更新平台路由管理后刷新网关本地缓存 |
| 网关 springdoc 配置 | 聚合各路由服务的文档地址 |

来源：[RedisRouteDefinitionWriter](src/main/java/cn/poria/common/gateway/support/RedisRouteDefinitionWriter.java) 和 [DynamicRouteAutoConfiguration](src/main/java/cn/poria/common/gateway/configuration/DynamicRouteAutoConfiguration.java)。

当前没有必须部署 Nacos 或 Eureka 的接入。需要部署实际网关和路由指向的业务服务；库本身没有独立管理后台或额外端口。完整网关配置见 [poria-gateway](../../poria-gateway/部署与配置.md)。本文未刷新线上路由。

## 需要填写的路由部署参数

此库没有独立 YAML 服务端口。在平台“路由管理”中按实际环境填写：

| 参数 | 部署示例 | 作用 |
|---|---|---|
| 路由标识 | poria-auth | 唯一标识一条路由 |
| URI | http://<认证服务地址>:3000 | 网关的真实目标服务 |
| Path 谓词 | /auth/** | 匹配认证请求 |
| filters | 按实际业务选择 | 控制路由过滤行为，避免额外重复去掉服务前缀 |

其他业务路由依次使用 UPMS 4000、base 8009。已有全局前缀处理器，部署前保持路由 filters 与它一致。
