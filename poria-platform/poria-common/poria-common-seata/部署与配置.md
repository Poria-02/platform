# poria-common-seata 部署与配置

## 模块作用与部署

分布式事务客户端库，不独立运行。实际使用时需要部署 Seata Server（事务协调器），并将本模块引入参与事务的业务服务。

当前 UPMS 的该依赖被注释，仓库未见 @GlobalTransactional 业务入口，因此不能当作已有完整跨服务事务。仅聚合模块包含它，不等于所有应用已经启用。

## 配置什么及作用

来源：[seata-config.yml](src/main/resources/seata-config.yml)、[SeataAutoConfiguration](src/main/java/cn/poria/common/seata/SeataAutoConfiguration.java)。

| 配置 / 环境变量 | 作用 |
|---|---|
| seata.enabled | 客户端开关，当前 true，仅在依赖实际被引入并加载时有意义 |
| seata.tx-service-group | 事务分组，当前 pigx_tx_group |
| seata.service.vgroup-mapping.pigx_tx_group | 将事务分组映射到集群，当前 default |
| seata.service.grouplist.default / SEATA_SERVER | 协调器地址，当前 poria-seata:8091，需要实际可达 |
| seata.registry.type、seata.config.type | 当前 file 模式，不要求仅为了此配置另部署 Nacos |
| seata.registry.file.name、seata.config.file.name | 当前引用 file.conf；仓库未见该文件，实际需要哪些补充项应与最终 Seata 版本核对 |
| seata.client.rm.*、tm-* | 锁检查、提交及回滚重试设置 |
| seata.client.undo.* | 回滚镜像校验、序列化及 undo_log 命名 |
| seata.service.disable-global-transaction | 是否禁用全局事务，当前 false |

## 使用前需要补齐什么

需要真实事务入口、参与方调用和数据源代理，并按所用模式准备回滚记录。当前配置类启用自动数据源代理；与其他代理方案并用时需确认没有重复代理。

POM 显式使用 Alibaba Seata starter 2025.0.0.0；BOM 中旧 seata.version 属性不能直接作为最终运行版本依据。Seata Server 版本需与实际解析的客户端依赖匹配，本次未解析依赖树或验证兼容性。

MySQL、Redis 部署与连接配置不展开；本文未执行分布式事务。

## 宿主服务部署参数示例

只有引入并使用分布式事务时填写；TC 地址替换为已部署的 Seata Server。

```yaml
seata:
  enabled: true
  tx-service-group: poria_tx_group
  service:
    vgroup-mapping:
      poria_tx_group: default
    grouplist:
      default: '<SeataServer地址>:8091'
    disable-global-transaction: false
  registry:
    type: file
  config:
    type: file
```

这里将事务分组示例改为 poria_tx_group，必须与对应映射一致；源码目前使用 pigx_tx_group，不能只改一处。file 模式的实际补充文件和其他参数需与所用 Seata 版本核对。业务事务入口、参与方及数据源代理是必要的代码接入项。
