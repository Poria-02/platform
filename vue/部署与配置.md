# Vue 前端部署与配置

## 模块作用与部署

管理平台页面，运行 Vue、Element Plus、Pinia 和 Vue Router。开发环境 Vite 默认监听 8000；生产环境由 Nginx、IIS 等静态站点服务器提供页面，站点端口由实际部署决定，生产不需要常驻 Vite 开发服务。

需要浏览器能访问配置的网关。使用定时任务内嵌页时，还需要浏览器能访问 XXL-Job Admin。MySQL、Redis 不属于前端配置。

配置文件：[开发环境](.env.development)、[生产环境](.env.production)。

## 需要配置什么

| 环境变量 | 作用与要求 |
|---|---|
| VITE_API_PREFIX | 浏览器业务 API 地址或前缀；为空时回退 /api，生产使用 /api 时需站点已有对应转发 |
| VITE_GATEWAY_TARGET | 仅用于 Vite 开发代理，当前默认网关 localhost:9999；生产不读取它建立代理 |
| VITE_AUTH_CLIENT_ID | OAuth 客户端 ID，需与 UPMS 客户端信息一致 |
| VITE_AUTH_CLIENT_SECRET | OAuth 客户端凭据，需与后端一致；VITE_* 值会进入前端产物，不能当作服务器端保密存储 |
| VITE_AUTH_ENCODE_KEY | 登录字段 AES 加密密钥，代码支持但当前环境文件未列；与 auth、UPMS 的 ENCODE_KEY 一致，UTF-8 编码后必须为 16 字节 |
| VITE_AUTH_USER_TYPE | 登录请求中的用户类型，当前 ADMIN_PWD |
| VITE_AUTH_SCOPE | 登录请求的 OAuth scope，当前 server |
| VITE_XXL_JOB_ADMIN_URL | 定时任务内嵌界面地址，填写浏览器可达的完整 Admin URL，如 http://服务器地址:9080/xxl-job-admin/ |

## 各配置对应什么功能

业务 API 经统一 HTTP 层处理并携带平台令牌。登录和刷新使用客户端认证；登录字段加密与 HTTPS 是不同层面的机制，浏览器 Web Crypto 需要受支持的安全上下文，生产页面应使用 HTTPS。

“系统管理 → 定时任务”是固定入口，要求平台正常登录；iframe 不附加平台令牌，用户另外使用 XXL-Job 账号登录。地址为空时显示提示。HTTPS 平台应配置 HTTPS Admin 地址，Admin 需允许 iframe 嵌入，浏览器需允许其登录 Cookie。只填地址不能绕过服务端响应头或跨站 Cookie 限制。

前端环境变量在启动或构建时读取：开发配置变更后由你重启已有实例，生产配置变更后由你重新构建部署。本文不执行这些操作。页面路径刷新需要站点回退到 index.html，业务 API 转发和调度中心 iframe 地址分别配置。

现有启动说明见 [README](README.md)。本次仅检查本地代码，未连接后端或验证 Admin 登录。

## 前端部署参数示例

填写到对应的 .env.development 或 .env.production。下面的客户端凭据和加密密钥需替换，并与后端配置对应。

```dotenv
VITE_API_PREFIX=/api
VITE_AUTH_CLIENT_ID=<UPMS维护的客户端ID>
VITE_AUTH_CLIENT_SECRET=<对应客户端凭据>
VITE_AUTH_ENCODE_KEY=<与auth和UPMS一致的16字节密钥>
VITE_AUTH_USER_TYPE=ADMIN_PWD
VITE_AUTH_SCOPE=server
VITE_XXL_JOB_ADMIN_URL=https://<调度中心域名>/xxl-job-admin/
```

仅开发环境另外设置网关代理目标：

```dotenv
VITE_GATEWAY_TARGET=http://<网关服务地址>:9999
```

业务 API 已使用独立后端域名时，将 VITE_API_PREFIX 替换为对应完整地址；不使用定时任务界面时 VITE_XXL_JOB_ADMIN_URL 可以为空。前端不需要新增 XXL-Job 代理参数。
